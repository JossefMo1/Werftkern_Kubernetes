# Werftkern v0.1.0-alpha.3 — experimental source-only alpha

**Experimental pre-release · NOT_PRODUCTION_READY · no CNCF certification.**

This repository-level alpha contains source and tests only. GitHub generates the
source archives; no executable packages, production signatures, support SLA or
reliability guarantee are included. It is intended for disposable lab evaluation.
The native runtime remains `0.2.0-dev.4`; the separate Kubernetes manager remains
`0.1.0-dev.3`. The alpha tag does not change either component version.

## Changes since alpha.2

- Prepared the README and contributor/security guidance for external review
  while retaining the project's experimental scope and ClusterPilot provenance.
- Reject malformed cloud provider inventory and create responses before a
  further paid resource creation can be admitted. Ambiguous create results
  retain their recovery journal instead of blindly repeating the request.
- Keep native rollouts in progress until retiring allocations acknowledge stop;
  the controller no longer reports readiness from stop intent alone.
- Pin the native CI toolchain and reachable-Go vulnerability check, and keep
  explicitly dispatched Ubuntu VM qualification separate from push concurrency.
- Record the production gaps and exact validation evidence in the
  [production-readiness review](../docs/validation/PRODUCTION-READINESS-2026-10-12.md).

## Validation and boundaries

The release workflow requires the native, Kubernetes contract and publication
audit checks to pass on the same `main` commit before creating this tag. A
separate real single-host Ubuntu VM run passed on commit
`2df522128514507507aaf6aee1fadcea6b3c1c6d`; it did not qualify a
multi-host, cloud or Kubernetes deployment and is not an exact-tag test.

Production qualification remains **BLOCKED** by the existing manifests and
[issue #16](https://github.com/JossefMo1/Werftkern_Kubernetes/issues/16).
Historical native dev.3-to-dev.4 package compatibility is unverified
([issue #8](https://github.com/JossefMo1/Werftkern_Kubernetes/issues/8)).
Main-branch protection and independent review remain tracked in
[issue #7](https://github.com/JossefMo1/Werftkern_Kubernetes/issues/7).
No real HA, cloud provider, PITR, live k0s lifecycle, retained storage,
independent security assessment or CNCF acceptance is claimed.

Do not use this source release for production clusters, customer workloads or
untrusted tenants. Review the [installation guidance](../README.md),
[security policy](../SECURITY.md) and
[publication checklist](../docs/OPEN-SOURCE-LAUNCH-CHECKLIST.md) before testing.
Earlier alpha tags remain immutable historical snapshots; alpha.1 retains its
old Go module path.
