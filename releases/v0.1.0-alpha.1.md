# Werftkern v0.1.0-alpha.1 — release notes (DRAFT)

**Status: Experimental source preview · NOT_PRODUCTION_READY · NOT RELEASED.**

These notes document a proposed first public **source-only pre-release**. They do
not certify a GitHub Release, signed artifact, successful CI run, CNCF acceptance,
security audit, or a production-grade Kubernetes distribution. The release must
not be published until the gates in [the publication checklist](../docs/OPEN-SOURCE-LAUNCH-CHECKLIST.md)
have been reviewed and passed by the repository owner.

## What's included in the current source tree

- **Werftkern Kubernetes backend** (`0.1.0-dev.3`): k0s/k0sctl-based plans for
  cluster creation, upgrades, scaling, local add-on assets, OIDC configuration,
  Sonobuoy invocation/parsing, and narrowly scoped cloud recovery workflows.
  These are mostly contract-tested; **real VM / Kubernetes qualification is not claimed**.
- **Werftkern Native Runtime** (`0.2.0-dev.4`): separate Go-based experimental
  container orchestration runtime, including TLS APIs, agents, scheduling,
  experimental HA, backups and upgrade contracts. It is **not Kubernetes**
  and not a replacement for the Kubernetes API.
- **Safety-oriented source controls**: Apache-2.0 license, attribution notices,
  contribution and security policies, tests, release-blocking qualification
  manifests and a historical secret scan prepared for CI.

## Important limitations

- **No real multi-node qualification** of cluster create/upgrade/scale,
  controller fencing, StatefulSet recovery, CSI restore, data/DB restore,
  partitions, load/soak, cert-manager/ACME, actual Keycloak login or Sonobuoy
  certified-conformance is established by the current evidence.
- The signed-evidence verifier does not create official release signatures,
  independently validate claims or grant CNCF certification.
- The Kubernetes manager's Debian package does **not** bundle k0s, Helm,
  Sonobuoy, images or charts. Its install alone does not create a cluster.
- The current Go module is `github.com/ClusterPilot-System/werftkern` rather
  than this repository's actual path. Import-path migration and compatibility
  must be reviewed before publishing install instructions.
- No security SLA, production support, RPO/RTO guarantee or compatibility
  guarantee is provided.

## Usage

For isolated, disposable evaluation only. Start with
[the Kubernetes backend guide](../docs/kubernetes/README-DE.md) and review
all prerequisites, exact asset checksums, SSH host trust and safety
confirmations. **Never execute privileged lab scripts on customer or production
hosts.**

## Release distribution policy

The intended first public pre-release is source-only (GitHub-generated
source archives), with no executable production binaries, unsigned `.deb`
assets, or signature/provenance claims. A tag and GitHub Release may be
created only after the pre-publication checklist and branch protections pass.
